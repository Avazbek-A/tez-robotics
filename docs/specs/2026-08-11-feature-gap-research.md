## Рекомендуемый порядок (волны)

1. **Зарядка** (6–7) — приоритет 1: без неё демо нечестное. Зависимостей нет; per-model пороги подключатся позже. Требует cancelOrder-хук (уже в PLAN2-HOOK-REQUESTS.md — один хук на преемпцию и дашборд).
2. **Зоны трафика, ядро** (4–5.5) — демо-реализм + паритет с RDS-чеклистом. Мягкий `zoneGate` в роутере обязателен сразу (анти-livelock).
3. **Auth** (3.5–4) — пилотный must-have; аудит-лог начинает копить историю, дальнейшие роуты рождаются под `requireRole`.
4. **Модели роботов** (5–7) — фундамент: per-model зарядные пороги (№1), footprint для зон (№2), флаги `sendsStartCharging/needsExplicitStopCharging`, гейт trajectory (№8′).
5. **Отчёты** (3–3.5) — поверх auth.
6. **Карта: LIF-модель + hot swap** (фазы A+B, 4–6) — закрывает «рестарт при смене карты»; самодостаточно без редактора.
7. **Редактор карт** (фазы C+D, 6–8) — вкладка дашборда + DXF-подложка.
8. **Периферия** (7–10) — перед мультиэтажом (лифт на 80% переиспользует её машинерию).
9. **Мультиэтаж** (6–9).

Попутно при первом заходе в VDA5050-адаптер: шов `buildEdge(fromNode, toNode, robotProfile)` (0.5).

## Ключевые архитектурные решения (из отчётов)

1. **Зарядка = обычный заказ с флагом `dispensable`** (openTCS), не отдельная подсистема. Фазовый тик вокруг венгерки: заказы → зарядка → парковка. Пин ячейки зарядки в резервациях; idle-yield не выталкивает CHARGING-робота. Наш sim-адаптер обязан слать `stopCharging` сам (VirtualAgvAdapter не едет, пока `charging==true` — расходится с допущением openTCS-адаптера).
2. **Зоны = семафоры ёмкости N на слое claim'ов** (RMF-стиль), не expand-set (openTCS-стиль): обобщается на N>1 и дешевле на сетке. Двухуровневая защита: мягкий фильтр в PIBT + жёсткий гейт в ReservationTable.
3. **LIF — нативный формат карты** + `tezExtensions` (зоны/зарядка/подложка отдельным namespace — LIF зон не несёт вообще). «Экспорт чистого LIF» всегда работает — маркетинговый козырь «поддерживаем VDMA LIF».
4. **Hot swap карты**: версии + двухфазная активация + graceful drain (v1); diff-активация — v2; миграция резерваций на лету — не делать.
5. **Auth свой** (~600 LOC): сессии в pg с SHA-256-хешем токена, argon2id, cookie same-origin — и та же кука аутентифицирует WS-upgrade (0 доп. кода для 10Hz-стрима).
6. **Периферийная операция — свойство ребра маршрута** с триггерами AFTER_ALLOCATION/AFTER_MOVEMENT и `completionRequired`; MovementCommand не уходит роботу, пока дверь не подтвердила открытие. Дверь/лифт = граница base/horizon в VDA5050.
7. **Мультиэтаж = отдельный grid на этаж + мета-граф**; лифт — эксклюзивный ресурс с session-владением (RMF). PIBT и резервации независимы per-этаж.
8. **Свободной навигации нет ни у кого из референсов** на уровне оркестратора — формулировка для тендеров: «гибридная навигация: SLAM-локализация роботов + графовая маршрутизация, как у SEER RDS».
9. **Модели роботов: factsheet — предзаполнение, не истина** (реальные вендоры заполняют мусорно); рабочие колонки редактируемы. Footprint — чебышёвский радиус на claim-слое, PIBT не трогаем; эрозия маски проходимости пер-модель + алерт связности.

## Известные технические риски (проверить до кодинга соответствующей волны)

- VirtualAgvAdapter и смена mapId/teleport (мультиэтаж) — возможно, нужен свой хук в sim.
- PIBT push-цепочки против one-way рёбер — затор в односторонних тупиках; правило «idle не паркуется в one-way/зонах».
- Зарядки стеной в колонке x==0 дефолтной карты — для демо рассредоточить.
- Очередь на зарядку при станций < роботов — openTCS не решает, проектируем сами (вытеснение sufficient-робота).
- shift-бакеты отчётов через полночь (смена 20:00–08:00).
