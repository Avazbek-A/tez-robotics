## Decisions

1. **WS frame growth (Plan2 #18)** — fix orchestrator-side so api/dashboard need zero changes: `snapshot()` returns all NON-terminal orders + only the most recent `opts.terminalOrderRetention` (default 200) terminal ones (completed/failed/canceled), newest-last, stable order. KPIs (`completions`, cycle times) already tracked separately — unaffected. `allOrders` internal list itself gets pruned (memory too, not just the view): on transition to terminal, if terminal count exceeds retention, drop oldest terminal orders from `allOrders`. OrderBook internals untouched.
2. **cancelOrder (Plan2 #17)** — implement the exact public method requested in docs/PLAN2-HOOK-REQUESTS.md §1: `cancelOrder(orderId: string): TransportOrder`; any non-terminal order → `canceled` via `book.transition`; if a robot holds it: best-effort `adapter.cancelMission`, `releaseAll` + own-cell re-claim (post-resolve invariant applies when called between ticks — cancelOrder is called from API handlers OUTSIDE the tick, so the next `resolveCurrentNodes` heals; still do the re-claim for safety, matching recovery-path shape), `setLeg(undefined)`. Throws on unknown/terminal. Then wire `DELETE /orders/:id` in packages/api to call it (200 with the order; 404 unknown; 409 already terminal).
3. **aedes ESM (Plan2 #13)** — `dev-broker.ts` stops top-level `import { createBroker } from "aedes"`: switch to lazy `const { default: aedesModule } = await import("aedes")` inside `startDevBroker` (or default-import + destructure — whichever survives BOTH tsx/vitest AND bare `node` on the built dist; prove with a bare-node smoke test in Task 4's build verification). Barrel export of `startDevBroker` stays.
4. **demo ids + BROKER_URL (Plan2 #14)** — unify on the sim scheme `sim-001..sim-00N`: packages/api's demo composition seeds FakeAdapter robots as `sim-001..` matching `spawnFleet`; `packages/api/src/main.ts` logs `BROKER_URL=<url>` line in vda mode so scripts/demo.mjs discovers the broker instead of 5s-fallback. Acceptance: `pnpm demo` boots and shows consistent ids; demo.mjs's discovery grep matches the new log line (read scripts/demo.mjs for its exact expected pattern — match IT, don't invent).
5. **#10 orchestrator smalls** — (a) offline-within-grace robot excluded from dispatch: `runDispatch` idle gate adds `rt.online`; (b) quarantine ERROR status no longer clobbered by next heartbeat: while `rt.quarantined`, incoming state events do not overwrite `rt.state.status` back from "ERROR" (keep position/battery updates flowing; only status is pinned until un-quarantine).
6. **Build pipeline (#2)** — tsup (devDependency, MIT) per node package (`shared, core, robot-interface, orchestrator, persistence, api, sim`), transpile-only (`bundle: false`, esm, dts off for speed — tsc --noEmit remains the typecheck), `main`/`exports` maps point at `dist/` with `publishConfig`-style dual: dev keeps tsx/vitest on src via `exports` condition order or keep tests importing src directly (tests already import src relatively — verify). Root script `build` runs `pnpm -r build` in dependency order (pnpm topo). Acceptance: `node packages/sim/dist/cli.js --help` (or equivalent smoke) works; `node packages/api/dist/main.js` boots demo mode headless and logs its startup line; existing dev flows (`pnpm demo`, vitest) unaffected. Dashboard keeps vite build, untouched.
7. **#11 cheap parts** — root README gains a packages/ section (one line per package); `RobotId` dual-definition documented as accepted at the cast-bridge site (one comment), NO type unification (risky refactor, deferred); edge-midpoint note already subsumed — strike in BACKLOG.
8. **Plan2 #15 verify** — root `pnpm -r test` ran dashboard 42/42 green post-d6191e0; confirm the root vitest workspace override exists and close the item with that commit ref.
